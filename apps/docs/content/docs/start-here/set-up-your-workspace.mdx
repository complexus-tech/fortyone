<Steps>
  <Step>
    **Create the workspace.** Choose a recognizable name and confirm the default
    terminology under **Settings → Workspace**.
  </Step>
  <Step>
    **Create the first team.** Give it a short code, a workflow, and only the
    labels the team will use immediately.
  </Step>
  <Step>
    **Invite members.** Add people with the smallest role they need. Team access
    can be managed separately from workspace membership.
  </Step>
  <Step>
    **Add real work.** Create a small set of current work items, assign owners,
    and move them through the workflow before importing a large backlog.
  </Step>
  <Step>
    **Connect useful tools.** Add only the integrations that remove an existing
    handoff: Slack, GitHub, Figma, Google Calendar, or Outlook Calendar.
  </Step>
</Steps>

## Recommended first-week setup

| Area          | A good first decision                                                |
| ------------- | -------------------------------------------------------------------- |
| Workflow      | Keep the number of states small and make “done” unambiguous          |
| Teams         | Organize around durable ownership, not every temporary project       |
| Labels        | Add labels when they support filtering or reporting                  |
| Working hours | Set realistic hours before enabling auto-scheduling                  |
| Notifications | Keep assignments and direct mentions on; reduce broad activity noise |
| Integrations  | Connect one workflow at a time and verify it with a real example     |

Once the basics work, explore [core concepts](/concepts),
[auto-scheduling](/product-guide/auto-scheduling), and the
[integration guides](/integrations).
