---
title: Outbound webhooks
description: Register secure endpoints, choose events, rotate secrets, and verify FortyOne deliveries.
---

Outbound webhook management requires an administrator PAT with
`webhooks:manage`. The endpoint must use public HTTPS on the supported port.
FortyOne resolves and validates destinations through its safe HTTP boundary;
private, loopback, link-local, and unsafe redirect targets are rejected.

| Method         | Path                                                              | Purpose                       |
| -------------- | ----------------------------------------------------------------- | ----------------------------- |
| `GET` / `POST` | `/api/v1/workspaces/{workspaceId}/webhook-endpoints`              | List or create endpoints      |
| `GET`          | `/api/v1/workspaces/{workspaceId}/webhook-endpoints/{endpointId}` | Read one endpoint             |
| `PUT`          | `.../{endpointId}/subscriptions`                                  | Replace all subscribed events |
| `POST`         | `.../{endpointId}/rotate-secret`                                  | Rotate the signing secret     |
| `POST`         | `.../{endpointId}/disable`                                        | Stop new deliveries           |

Create an endpoint:

```sh
curl --fail-with-body \
  --request POST \
  --header "Authorization: Bearer ${FORTYONE_TOKEN}" \
  --header "Content-Type: application/json" \
  --data '{
    "name": "Production event sink",
    "url": "https://integrations.example.com/webhooks/fortyone",
    "subscriptions": ["story.created", "story.updated", "comment.created"]
  }' \
  "https://api.fortyone.app/api/v1/workspaces/${FORTYONE_WORKSPACE_ID}/webhook-endpoints"
```

The `201` response contains `signingSecret` exactly once. Store it before
discarding the response. Listing or reading the endpoint never returns it.

Supported event types are `story.created`, `story.updated`, `story.deleted`,
`comment.created`, `comment.updated`, and `comment.deleted`. Replacing
subscriptions is a full replacement, not an additive patch.

## Verify every delivery

Deliveries use `Content-Type: application/json` and include `Webhook-Id`,
`Webhook-Timestamp`, and `Webhook-Signature`. Delivery bodies are valid JSON,
non-empty, and no larger than 256 KiB. Compute HMAC-SHA256 over these exact
bytes:

```text
<Webhook-Id>.<Webhook-Timestamp>.<raw request body>
```

Compare the base64 digest in each `v1,<digest>` signature using a constant-time
comparison. Verify the raw body before parsing JSON, reject stale timestamps,
and deduplicate using `Webhook-Id`. During secret rotation the signature header
can carry current and previous signatures; accept either valid signature only
until `previousSecretExpiresAt`.

The JSON envelope contains `id`, `type`, `payload_version`, `occurred_at`, and
`data`. Route on `type` and `payload_version`, ignore unknown additive data
fields, and return a `2xx` only after the delivery is safely recorded.

Comment events use payload version `1` and expose identifiers only:

```json
{
  "id": "1f128146-a75d-4c16-a5ee-c87f994e99d7",
  "type": "comment.updated",
  "payload_version": 1,
  "occurred_at": "2026-08-28T11:30:00Z",
  "data": {
    "comment_id": "48bde60f-d1e4-46f5-bd75-f32a193e85cc",
    "story_id": "406741c5-5cff-4673-a3bb-4036cc6c78c9",
    "parent_id": null
  }
}
```

The contract never includes comment text, mention lists, user profiles, email
addresses, access tokens, provider metadata, or secrets. Treat event `id` as
the idempotency key. Deleting a parent invalidates its reply subtree; the
explicit parent deletion is the delivered event.

Disable an endpoint when it is no longer required. Disabled endpoints cannot
be rotated and do not receive newly created deliveries.

The [SDK previews](./sdks) include exact-byte verifiers for TypeScript and Go.
The runnable Go external-integration sample also demonstrates a durable local
inbox; replace that file with a database uniqueness constraint and durable
payload record in production.
