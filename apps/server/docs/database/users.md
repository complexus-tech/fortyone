# Users persistence contract

The users module owns its production PostgreSQL access under
`internal/modules/users/repository`. Reviewed queries live in `queries`, SQLC
v1.31.1 generates native pgx/v5 bindings in `sqlc`, and the handwritten adapter
maps those generated values to the service package's domain models. Generated
types never cross the repository boundary.

## Capability map

| Capability                                               | Reviewed SQL                         | Handwritten adapter                                                  |
| -------------------------------------------------------- | ------------------------------------ | -------------------------------------------------------------------- |
| account create, read, update, activation, workspace list | `queries/accounts.sql`               | `accounts.go`                                                        |
| automation preference defaults and typed patches         | `queries/automation_preferences.sql` | `automation_preferences.go`                                          |
| OAuth identity lookup, linking, and account resolution   | `queries/external_identities.sql`    | `identities.go`                                                      |
| browser-session epoch resolution                         | `queries/browser_sessions.sql`       | `browser_sessions.go`                                                |
| bounded inactivity and deactivation maintenance          | `queries/maintenance.sql`            | `maintenance.go`                                                     |
| private user memory CRUD                                 | `queries/memories.sql`               | `memories.go`                                                        |
| verification-code quota, issue, consume, and invalidate  | `queries/verification_tokens.sql`    | `verification_tokens.go`                                             |
| explicit generated-to-domain conversion                  | generated rows from every query file | `account_mappers.go`, `workspace_mapper.go`, `capability_mappers.go` |

`users.go` owns only construction and transaction binding. It creates a
module-local SQLC query object from `*pgxpool.Pool`, and it uses the platform
transactor for repository-owned transactions.

## Account visibility and workspace scope

The repository deliberately exposes two different account visibility rules:

- Interactive account reads return active users only. An inactive or missing
  account maps to `users.ErrNotFound`.
- Identity-resolution and actor-hydration reads can request any status. This is
  required to link an external identity to an existing inactive account without
  silently reactivating it, and to render historical system or inactive actors.

Workspace lists require an active workspace membership and exclude system
accounts. When a team filter is present, the team membership join also proves
that the team belongs to the supplied workspace. A globally valid team ID from
another workspace therefore returns an empty list rather than leaking users.
Search, limit, and offset are bound parameters. The adapter bounds integer
conversion before calling the generated query.

`last_used_workspace_id` is only set when the user has an active membership in
the target workspace. It is a convenience pointer, not authorization state.

## Private capability scope

User memories are private to the exact `(user_id, workspace_id)` pair. Every
create, list, update, and delete also proves that the user is active and remains
an active workspace member at statement execution time. A missing, inactive,
cross-user, or cross-workspace mutation maps to `users.ErrMemoryNotFound`; the
shared outcome avoids disclosing whether another user's memory exists.

Automation preferences use the same active membership proof. The get operation
creates the documented defaults only for an eligible member. Updates use
explicit `set_*` booleans generated by SQLC, so a caller can distinguish an
omitted field from an intentional `false` value without building SQL strings.

## External identity transaction

External identity resolution is one repository-owned pgx transaction:

1. take a transaction-scoped advisory lock for the normalized provider,
   issuer, and subject;
2. return the already-linked account when the identity exists;
3. otherwise lock identity creation for the normalized email;
4. reuse an existing account, including an inactive account, or create one;
5. insert the identity link; and
6. commit both account and identity state together.

Concurrent first-login requests therefore converge on one user and one identity
row. The adapter maps PostgreSQL unique violations to `users.ErrEmailTaken`
where the domain contract exposes an email conflict. It never activates an
existing inactive account inside the identity-link transaction.

After the email or OAuth identity has been verified, the service may invoke the
separate typed reactivation mutation. That mutation accepts only
`login_reactivation_policy = 'verified_sign_in'`. Administrator-disabled
(`admin_only`) and ambiguous legacy (`legacy_admin_review`) accounts remain
inactive and map to the same generic invalid-credentials result as an unknown
account. The HTTP layer issues no session cookie for any denied reactivation.
Administrator enable is the only path that clears those policies.

## Verification-code security

Verification codes are never stored in plaintext for newly issued rows. The
service supplies a purpose-bound, versioned HMAC digest and the repository
stores only the digest metadata. Issuance is serialized by a transaction-scoped
advisory lock derived from email and token purpose; the recent-issue count and
insert share that transaction, making the quota atomic under concurrency.

Consumption is one SQL statement. It locates an unexpired, unused row using the
email, approved purposes, digest candidates, key IDs, and versions; locks the
candidate; and sets `used_at` only if it is still unused. Concurrent consumers
can therefore succeed at most once. During the documented expand window, rows
whose digest is null may still match the legacy plaintext column. New writes do
not populate that column.

The adapter validates token purposes before binding them as text-array values.
This avoids relying on runtime registration of PostgreSQL's custom enum-array
OID while retaining an explicit domain whitelist and a database enum column.
Unique digest collisions map to `users.ErrTokenCollision`, allowing the service
to generate a bounded number of replacement codes.

The repository exposes the active account's monotonic browser-session epoch.
Issuance stores that epoch beside the user ID in Redis; middleware rechecks the
active account and exact epoch on every request. Deactivation and explicit
revocation advance the epoch atomically, while activation never resets it. The
complete cookie, Redis, and rollout contract is documented in
[`docs/security/browser-sessions.md`](../security/browser-sessions.md).

## Transaction ownership

Repositories own all transactions except one explicit compatibility bridge:
workspace bootstrap currently calls `UpdateUserWorkspaceWithTx` with its
caller-owned `pgx.Tx`. The users adapter immediately binds that transaction with
`Queries.WithTx`; it never exposes generated queries and never commits or rolls
back the caller's transaction. This narrow bridge remains until workspace
bootstrap owns a module-level unit-of-work port.

Tests must prove both sides of that contract: an update is visible inside the
caller's transaction, and caller rollback removes it.

## Error and result semantics

| Database outcome                                                | Repository outcome                            |
| --------------------------------------------------------------- | --------------------------------------------- |
| missing or inactive interactive account                         | `users.ErrNotFound`                           |
| duplicate account email                                         | `users.ErrEmailTaken`                         |
| ineligible last-used workspace update                           | `users.ErrWorkspaceNotFound`                  |
| missing or out-of-scope private memory                          | `users.ErrMemoryNotFound`                     |
| missing or ineligible automation preferences                    | `users.ErrNotFound`                           |
| verification issue quota reached                                | `users.ErrTooManyAttempts`                    |
| verification digest collision                                   | `users.ErrTokenCollision`                     |
| invalid, expired, used, or wrong-purpose verification candidate | `users.ErrInvalidToken`                       |
| denied or unknown sign-in reactivation                          | `users.ErrInvalidCredentials`                 |
| inactive or missing browser-session account                     | invalid browser session                       |
| zero-row list                                                   | non-nil empty slice                           |
| unexpected database failure                                     | wrapped error preserving the PostgreSQL cause |

## Verification

Ordinary repository tests use the generated `Querier` interface to prove typed
parameter mapping, explicit row conversion, SQLSTATE mapping, private scope, and
transaction binding. SQL source contract tests retain the critical workspace,
membership, active-user, system-actor, one-time-use, and explicit-column
predicates.

Integration-tag tests apply the real migration chain to disposable PostgreSQL
18 databases. They cover two-workspace negative cases, inactive and system
actors, private memories, preferences, account lifecycle, caller rollback,
concurrent external identity resolution, atomic issuance quotas, absence of new
plaintext codes, purpose binding, legacy compatibility, and concurrent
single-use consumption.

Run from `apps/server`:

```bash
go test -race ./internal/modules/users/repository ./internal/modules/users/service
TEST_DATABASE_URL='postgresql://...' \
  go test -race -tags=integration -count=1 ./internal/modules/users/repository
make sqlc-check
SQLC_DATABASE_URL='postgresql://...' make sqlc-vet
go test -race ./internal/bootstrap/architecture
```
