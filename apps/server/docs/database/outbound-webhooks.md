# Outbound webhook data model and query guide

Migration `000159_outbound_developer_webhooks` introduces the durable customer
webhook model. Application access lives in
`internal/modules/outboundwebhooks/repository/queries` and is generated by the
`outbound_webhooks` SQLC block. Production repository code uses native pgx and
the shared transaction runner; SQLx is not a fallback for this module.

## Tables and invariants

| Table                                | Purpose                                                   | Important invariants                                                                                          |
| ------------------------------------ | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `outbound_webhook_endpoints`         | tenant-owned destination and encrypted secret generations | human owner principal; HTTPS URL; active/disabled state shape; current/previous secret generation consistency |
| `outbound_webhook_subscriptions`     | endpoint-to-declared-event catalog                        | endpoint/workspace composite FK; unique endpoint/event pair                                                   |
| `outbound_webhook_events`            | stable product event identity and semantic payload        | global event ID; workspace identity; payload version 1; object `jsonb`; created after occurrence              |
| `outbound_webhook_deliveries`        | exact per-endpoint body and delivery state                | unique event/endpoint; lease-state shape; at most 32 attempts; terminal timestamp shape                       |
| `outbound_webhook_delivery_attempts` | immutable sanitized network outcome                       | unique delivery/attempt number; bounded status/body-size/digest/duration                                      |
| `outbound_webhook_audit_events`      | immutable management history                              | stable actor attribution and bounded machine metadata                                                         |

The audit and attempt ledgers have database triggers that reject updates and
deletes with SQLSTATE `55000`. Endpoint/workspace and event/workspace composite
keys make tenant identity available to every child foreign key.

## Endpoint queries

Creation runs in a serializable transaction:

1. `EnsureOutboundWebhookOwnerActive` rechecks principal, active user, and live membership.
2. `CreateOutboundWebhookEndpoint` inserts the encrypted generation-1 secret.
3. `AddOutboundWebhookSubscription` inserts each validated catalog event.
4. `RecordOutboundWebhookAuditEvent` records the actor and request ID.

Any failure rolls back the endpoint, subscriptions, and audit event together.
The repository never accepts a generated SQLC model from its caller.

Get/list queries always include `workspace_id`. They return subscriptions in a
typed text array, avoiding a list-time N+1 query. Listing uses descending
`(created_at, endpoint_id)` keyset pagination. A cursor must contain both
values, and the service fetches `page_size + 1` to determine whether to issue a
next cursor. HTTP adapters sign that cursor; raw timestamps and IDs are not a
public continuation token.

Subscription replacement locks the endpoint, replaces the event set,
increments `subscription_generation`, and cancels pending/retry deliveries from
the previous generation. A worker also joins the current subscription and
generation during claim, so stale work cannot escape a concurrent replacement.

Secret rotation updates current and previous envelopes in one compare-and-swap
statement guarded by endpoint, workspace, active status, and expected current
generation. A zero-row result is a concurrency conflict.

## Event publication and semantic idempotency

`PublishEvent` runs in one serializable transaction. It inserts the stable event
and fans out only to active endpoints whose current owner principal, subject
user, and workspace membership are active. The exact pre-encoded envelope is
copied into each delivery.

`event_id` is the idempotency key. On a unique violation, the repository reads
the existing canonical identity and compares workspace, type, payload version,
subject, actor, credential, occurrence time, and payload. Payload equality is
computed by PostgreSQL `jsonb`, not byte equality, because PostgreSQL normalizes
object whitespace and key order. A true replay returns no new delivery IDs; a
different meaning under the same ID returns a conflict.

The fan-out insert uses the unique `(event_id, endpoint_id)` constraint as a
second idempotency fence. No application-side check-then-insert race is used.

## Claim fairness and endpoint ordering

Claiming has two SQL steps inside one transaction:

1. `LockNextOutboundWebhookEndpointForDelivery` chooses the least recently
   claimed eligible endpoint with `FOR UPDATE ... SKIP LOCKED`.
2. `ClaimNextOutboundWebhookDelivery` leases the oldest eligible delivery for
   that endpoint and increments its attempt count.

An endpoint with any `delivering` row is excluded from step one. This provides
one in-flight request per destination while allowing workers to progress on
other endpoints. The endpoint owner and subscription generation are rechecked
in SQL at claim time.

The lease token is random and the expiry is 30 seconds. `RecoverExpiredLeases`
returns expired delivering rows to retry state. Completion requires delivery
status `delivering`, exact lease token, and exact attempt number.

## Completion transaction

`CompleteAttempt` validates bounded values before opening a transaction:

1. insert immutable sanitized attempt;
2. update the leased delivery to success, retry, failure, or cancellation;
3. reset endpoint health on success, or increment/disable it only when the
   outcome represents a destination failure.

An operational vault outage intentionally completes the delivery attempt
without changing endpoint health. This distinction prevents an internal key
incident from disabling customer endpoints.

If the lease update affects zero rows, the entire transaction—including the
attempt insert—rolls back and the caller receives `ErrDeliveryLeaseLost`.

## Query review checklist

When changing this module:

- keep workspace predicates on every endpoint and child lookup;
- preserve live owner checks at both fan-out and claim;
- preserve subscription-generation fencing;
- use SQLC parameters and `CAST(...)`, never string-built SQL;
- do not expose secret envelope columns from read models;
- do not return response bodies or arbitrary errors from attempts;
- preserve event and delivery idempotency constraints;
- preserve endpoint-serial claim behavior;
- add a new migration for schema changes; never edit migration `000159` after it has run;
- regenerate SQLC and run PostgreSQL 18 integration tests.
